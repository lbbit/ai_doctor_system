# 系统化排错

来源：obra/superpowers `systematic-debugging`，来源链接：https://github.com/obra/superpowers/tree/main/skills/systematic-debugging

## 铁律

没有完成根因调查，不得提出修复。

## 四阶段

1. **根因调查**：完整阅读错误、稳定复现、检查近期变更和环境差异，沿调用栈/数据流向上追到错误值的来源。
2. **模式分析**：找到同模块可工作的实现，逐项比较输入、配置、依赖、边界和时序差异。
3. **单一假设**：明确写出“我认为 X 是根因，因为 Y”，用最小实验一次只改变一个变量。
4. **实施修复**：先写回归测试并观察 RED，再修根因；验证局部、全量和实际用户路径。

## 复杂链路

API→数据库→队列→worker→对象存储/LLM 失败时，在边界记录输入/输出、配置是否传递和状态变化；先确定断点，再修改断点所属组件。

## 三次失败规则

同一问题连续三次修复仍失败，停止叠加补丁，重新审视模块边界、共享状态、重试和架构假设，并把判断写入计划/日志。
