# Web 端到端测试技能

## 何时使用

- 单测/构建都绿，但用户反馈"基本功能不可用"（本项目真实发生过：白屏、卡在抽取中、草稿全是噪声）。
- 新增页面、改动交互或状态机后，需要证明**真实浏览器里**可用。
- 需要留存可复现的验收证据（截图 + DOM 文本 + 网络错误）。

## 铁律

1. **单测通过 ≠ 功能可用**：任何前端改动至少做一次真实浏览器检查。
2. **只看 DOM 文本，不靠猜**：用可访问性快照/`innerText` 断言，不用肉眼想象布局。
3. **记录三类证据**：DOM 文本、控制台错误、关键接口响应（状态码 + 关键字段）。
4. **禁止在生产数据上做破坏性测试**：用独立测试账号与独立 Subject。
5. **发现缺陷先复现再修**：写一个失败用例描述"用户做了什么、期望什么、实际什么"。

## 标准流程

### 1. 准备

```bash
# 服务健康（六容器）
docker ps --format "{{.Names}}\t{{.Status}}"
# API 冒烟
curl -s http://localhost:8000/healthz
# 前端可达
curl -sI http://localhost:8080 | head -1
```

准备一个专用测试账号（不要复用真实用户），例如 `uicheck@example.com`。

### 2. 打开页面并读取状态

优先用可访问性快照（比截图省 token 且可断言）。若需要看视觉布局，**先压缩截图**：

```bash
python scripts/shrink_image.py <截图.png> --out /tmp/small.png --max-side 1100
```

### 3. 逐功能验收清单（本项目 P0）

| # | 场景 | 关键断言 |
|---|---|---|
| 1 | 注册并自动登录 | 跳转 `/app/timeline`；localStorage 有 token；顶部显示默认 Subject |
| 2 | 登录失败 | 错误码文案友好（非 "Network Error"），不清空已填邮箱 |
| 3 | 切换 Subject | 列表/时间线/趋势随档案变化；切换后刷新仍保持 |
| 4 | 无 Subject 写入 | 上传被阻断并提示选档（422 语义） |
| 5 | 上传报告 | 返回 201；列表出现新文档且状态 `pending` |
| 6 | 抽取进度 | 详情页显示阶段文案 + `已完成 n/总页数` + 已用时；**不允许长时间停在旧数字** |
| 7 | 抽取完成 | 状态变"待确认"；草稿条目是可读指标名 + 数值 + 参考区间，且**无**"专线/400"类噪声 |
| 8 | 草稿分组 | 异常项在最前；"只看需确认"可切换；批量确认/拒绝按钮可用 |
| 9 | 行内修正 | 改指标名后保存，状态变"已修正"；确认后入库名称以修正值为准 |
| 10 | 确认入库 | 状态变"已确认"；时间线立即出现该事件；重复确认被拒（409） |
| 11 | 重新抽取 | 异步入队；详情页回到进度态；完成后出现 v2 草稿与差异提示 |
| 12 | 时间线 | 按年月分组倒序；类型筛选生效；空档案显示引导而非空白报错 |
| 13 | 趋势折线 | 选指标后出图；数据点 <2 时显示"数据不足"而非空图 |
| 14 | 问诊 | SSE 流式输出；回答含 `[依据：…]`；无依据时出现"依据有限"声明 |
| 15 | 红旗提示 | 出现"胸痛放射/偏瘫"等，顶部强制出现"立即就医"卡片 |
| 16 | 原件回链 | 引用可点，签名链接可打开原件（过期自动刷新） |
| 17 | 设置页 | 脱敏开关/免责声明版本展示；修改后刷新仍生效 |
| 18 | 审计 | 确认/归档/重抽均有审计记录，含前后值 |
| 19 | 隔离 | 用 A 账号访问 B 的文档 ID → 404（不泄露存在性） |
| 20 | 移动端宽度 | 375px 下主流程可完成，无横向滚动遮挡关键按钮 |

### 4. 常见坑（本项目实测）

- **后台标签页轮询暂停**：`react-query` 在 `visibilityState=hidden` 时不刷新，验收前先 `bringToFront` 或直接 reload，不要据此判定"卡死"。
- **404 可能是正常的跨档隔离**：先确认当前登录账号与文档归属。
- **控制台 404 不代表功能坏**：本项目的 favicon/可选静态资源会有 404，需点开看具体 URL。
- **中文控制台乱码**：PowerShell 默认 GBK，断言请写到 UTF-8 文件再读取，或直接用 DOM 文本。
- **图片上传要用纯 ASCII 表单字段**：Windows Git Bash 传非 ASCII argv 会破坏 multipart。

### 5. 缺陷记录模板

```markdown
### 现象
用户操作：<步骤>
期望：<可观测结果>
实际：<截图 / DOM 片段 / 状态码>
### 根因
<指到具体文件:行，说明为什么>
### 修复与验证
<改动点 + 重新验证的命令与结果>
```

## 与项目规范的衔接

- 遵循根目录 `AGENTS.md`：先定位再改动、TDD、完成前验证。
- 验收结论回写 `PLAN.md`，不要只在对话里说"通过了"。
- 涉及医疗数据：测试账号与样本不得含真实患者信息，敏感字段须脱敏。
